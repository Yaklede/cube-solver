# 장치 연동 확장 로드맵

## 목적

향후 Arduino, 전용 큐브 로봇, USB/Serial/BLE 기반 장치를 연결해 큐브를 대신 맞추거나 특정 학습 케이스로 섞는 기능을 확장한다. 현재 단계에서는 실제 모터 제어를 구현하지 않고, 앱과 장치 사이의 안전한 명령 계약을 먼저 고정한다.

## 지원 대상 모드

| 모드 | 목표 | 앱 역할 | 장치 역할 |
| --- | --- | --- | --- |
| `full-solve` | 현재 큐브 전체 맞춤 | 6면 스캔, 상태 검증, 풀이 생성, 시작 기준 안내 | 검증된 풀이 수순 수행 |
| `full-scramble` | 일반 연습용 전체 섞기 | 표준 스크램블 생성, 수행 후 상태 검증 | 스크램블 수순 수행 |
| `d-cross` | Cross 계획 연습 | Cross 엣지 위치 표시, 15초 인스펙션, 완료 검증 | Cross 연습 상태 준비 |
| `f2l` | F2L 페어 반복 연습 | 페어/슬롯 목표 표시, 성공/실패 기록 | 특정 F2L 케이스 준비 |
| `oll` | OLL 케이스 반복 연습 | 케이스 이름, 공식 카드, 수행 시간 기록 | 선택 OLL 케이스 준비 |
| `pll` | PLL 케이스 반복 연습 | 유사 PLL 비교, 평균 수행 시간 기록 | 선택 PLL 케이스 준비 |

## 명령 계약 v0

코드 기준 계약은 `src/core/device.ts`에 둔다.

- `DevicePracticePlan`: 학습 모드별 목표, 사용자 행동, 장치 행동, 카메라 체크포인트, 안전 조건
- `DeviceCommandPreview`: 실제 장치로 보내기 전 UI가 확인해야 하는 명령 미리보기
- 모든 명령은 `requiresCameraCheck`, `requiresUserConfirmation`을 기본으로 가진다.
- 기본 시작 기준은 `U/F/R`이며, 사용자가 선택한 흰색 아래/위 기준과 장치 좌표계가 다르면 변환 계층을 추가한다.

## 안전 원칙

1. 카메라로 큐브 상태가 유효하다고 확인되기 전에는 장치 명령을 전송하지 않는다.
2. 사용자가 명시적으로 시작을 누르기 전에는 모터를 동작시키지 않는다.
3. 장치 동작 중 강제 정지와 timeout 처리를 반드시 둔다.
4. 큐브 고정 상태, 손 끼임 위험, 장치 통신 오류를 UI에서 분리된 상태로 표시한다.
5. 장치가 스크램블을 만든 뒤에도 앱은 다시 카메라로 상태를 검증한다.

## 구현 순서

1. 현재 단계: `src/core/device.ts` 계약, 학습 화면의 장치 확장 패널, 단위 테스트
2. 다음 단계: mock transport와 설정 화면의 연결 상태 표시
3. 이후 단계: Web Serial 기반 브라우저 연결 또는 Tauri 플러그인 기반 데스크톱 연결
4. 실기기 단계: ACK/timeout/error protocol, emergency stop, 장치 calibration
5. 학습 개인화 단계: 약점 OLL/PLL/F2L/D-Cross 케이스를 장치가 자동 출제

## 검증 기준

- `npm run test -- tests/device.test.ts`
- 장치가 없어도 학습 화면에서 모드별 목표와 command preview가 표시된다.
- 실제 장치 연결 전까지는 모든 명령이 미리보기와 확인 단계에 머문다.
